# Процедурная реализация алгоритмов сеансового обслуживания VR-арены

Учебная практика, этап 2 (аналитический). Прототип алгоритмов А1–А4 на Python 3.10+,
без внешних зависимостей. Данные хранятся в памяти (физическая БД — на следующих этапах).

| Алгоритм | Модуль | Рисунок блок-схемы |
|---|---|---|
| А1 Проверка доступности слота | `vr_arena/a1_slots.py` | Рис. 10 |
| А2 Контроль длительности сеанса | `vr_arena/a2_session_time.py` | Рис. 11 |
| А3 Статусы комплектов оборудования | `vr_arena/a3_equipment.py` | Рис. 12, 13 |
| А4 Отмена, перенос, неявка | `vr_arena/a4_bookings.py` | Рис. 14 |

Модели данных и параметры — `vr_arena/models.py` (соответствуют ER-диаграмме, рис. 9).

## Запуск (из корня проекта)

    python demo.py                        # демонстрационный сценарий одного дня
    python run_cases.py                   # таблица «ожидалось / получено» по всем кейсам
    python -m unittest discover -v        # автоматические тесты

## Допущения прототипа
- Одна арена, время без часового пояса, длительность в минутах.
- Интервал на подготовку (10 мин), порог предупреждения (5 мин), срок ожидания группы
  (15 мин), шаг поиска альтернатив (15 мин) — предполагаемые значения, не из источников.
- Статус комплекта вносит оператор вручную; интеграции с гарнитурами нет.
- Одновременная работа нескольких администраторов не моделируется.
