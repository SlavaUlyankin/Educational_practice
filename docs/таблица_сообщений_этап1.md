# Обмен сообщениями при изменении брони

| Сообщение | Отправитель → получатель | Содержание и результат |
|---|---|---|
| ML5.1 | Клиент → администратор VR-арены | Запрос отмены; запускается обработка ESP1 и поиск активной брони в DS1. |
| ML5.2 | Клиент → администратор VR-арены | Запрос переноса с новым временем и при необходимости площадкой; запускается ESP1. |
| ML6.1 | Администратор VR-арены → клиент | Подтверждение отмены после изменения статуса и фиксации события. |
| ML6.2 | Администратор VR-арены → клиент | Подтверждение переноса после проверки слота, обновления брони и записи прежних и новых значений. |
| ML6.3 | Администратор VR-арены → клиент | Отказ, отсутствие активной брони либо альтернативы; при неудачном переносе бронь не изменяется. |

После отмены SP2 для отменённой брони не выполняется. После успешного переноса дальнейшее обслуживание использует актуальное время брони. Обработка других заявок не прерывается.

Рабочие рисунки 1, 2 и 4 подготовлены как изображения с основными обозначениями BPMN; отдельного машинно проверяемого BPMN-файла нет. На странице DOCX подписи схем мелкие. Этот вариант требует согласования, если требуется полная проверяемая BPMN-модель или повышенная читаемость печатной версии.
